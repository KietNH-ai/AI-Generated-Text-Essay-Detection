# 02 — Tree-Based ML Experiments

## Purpose and implementation

The tree-model experiments are part of the shared classical workflow, primarily in `notebooks/04_important_feature.ipynb` and `notebooks/05_LG_RF_LGBM_XGB_SVM.ipynb`. They are not a separate end-to-end pipeline from the linear models.

Notebook 05 compares Random Forest, LightGBM, and XGBoost alongside Logistic Regression and SVM. The primary representation combines TF-IDF text features with scaled engineered numeric features. Notebook 04 uses Random Forest for feature analysis and comparisons of selected linguistic measurements.

## Inputs and features

The notebook workflow starts from `data/processed/processed_data.csv` and uses the feature-enriched table/columns prepared by its setup cells. Shared path constants are defined in `src/path.py`; the generated processed tables are local artifacts and may need to be regenerated by running notebooks 02 and 04 in order.

Record the actual feature columns and preprocessing used for each reported experiment. Results from a numeric-feature-only analysis are not directly comparable to the combined TF-IDF-plus-numeric experiment.

## Split, fitting, and evaluation

Notebook 05 uses a stratified 80/20 train/test split with a fixed seed and stratified five-fold cross-validation on the training portion. Vectorization and scaling must be learned from the training data only. The held-out test set is reserved for final evaluation.

The notebook reports classification metrics including precision, recall, F1, and ROC-AUC (using probabilities or decision scores as available). Thresholds and class-weight settings are model-specific; use the executed notebook configuration when describing a result rather than assuming a universal threshold.

## Interpretation

Random Forest and boosted-tree importance scores describe how a fitted model uses its input features. They are model-dependent associations, not causal evidence. Correlated or redundant predictors can change importance rankings.

## Reusable API

`src/pipelinebuilder.py` also supports Random Forest, XGBoost, and LightGBM through `PipelineFactory`. It is an available reusable implementation, but notebooks 04/05 define the experiment protocol documented above. The API currently writes to `results/` and `models/`, while `src/path.py` defines project notebook artifacts under `result/`; keep this path distinction in mind when locating generated output.
