# Pipeline 03 --- Deep Learning / Transformer Models

## 1. Purpose

This branch evaluates transformer-based deep-learning models for
AI-generated essay detection.

The main candidate models defined in the project are:

-   DistilBERT;
-   RoBERTa.

This branch provides the deep-learning counterpart to the classical
TF-IDF and tree-based approaches.

## 2. Input

The primary input is the essay text.

Unlike classical models, transformer models do not require TF-IDF as
their primary text representation.

Typical flow:

``` text
Cleaned essay text
    ↓
Tokenizer
    ↓
Token IDs + attention mask
    ↓
Pretrained transformer
    ↓
Classification head
    ↓
Fine-tuning
    ↓
Prediction probability
    ↓
Precision / Recall
```

## 3. Data split

The dataset must be separated before model training into the project's
defined training, validation, and test partitions.

The test partition must remain isolated until final evaluation.

Any decision involving:

-   hyperparameters;
-   number of epochs;
-   classification threshold;
-   model selection;

should be based on training/validation data rather than the test set.

## 4. Tokenization

Each essay is converted into the token representation expected by the
selected pretrained model.

The tokenizer must correspond to the selected transformer architecture.

Long essays may exceed the model's maximum sequence length. The handling
strategy must therefore be explicitly documented for the experiment, for
example truncation or a suitable chunking strategy.

## 5. Fine-tuning

The pretrained transformer is fine-tuned for binary classification.

Conceptually:

``` text
Pretrained DistilBERT / RoBERTa
              ↓
        Classification head
              ↓
       Human vs AI label
```

Training parameters should be recorded for reproducibility, including:

-   learning rate;
-   batch size;
-   number of epochs;
-   maximum sequence length;
-   optimizer;
-   random seed.

## 6. Evaluation

The primary metrics remain:

-   **Precision**
-   **Recall**

The evaluation procedure must match the classical branches as closely as
possible.

This allows the project to compare model families rather than comparing
different evaluation protocols.

## 7. Relation to Research Questions

This branch directly supports Research Question 2 by providing the
transformer side of the comparison:

`TF-IDF + classical ML` vs `fine-tuned DistilBERT/RoBERTa`.

It also supports Research Question 3 when the trained model is evaluated
on text generated by LLMs that were not represented in its training
data.

## 8. Generalization experiment

For Research Question 3, the important distinction is between:

-   **in-distribution evaluation**: training and testing data have
    similar generation sources;
-   **cross-LLM evaluation**: the model is tested on text generated by a
    different LLM.

The second setup is important because a detector that performs well on
one generator may rely on generator-specific patterns rather than
general properties of AI-generated writing.

## 9. Expected output

Each experiment should produce:

-   tokenizer/model configuration;
-   fine-tuned model;
-   validation results;
-   test predictions;
-   Precision;
-   Recall;
-   cross-LLM results when applicable;
-   training configuration for reproducibility.
