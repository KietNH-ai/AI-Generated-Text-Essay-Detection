# AI-Generated Text (Essay) Detection

Detection of AI-generated student essays through linguistic feature analysis, traditional machine learning, and fine-tuned transformers — with a dedicated cross-LLM generalization experiment.

---

## 1. Project Overview

The rapid development of Large Language Models (LLMs) such as GPT, Claude, and Gemini has made AI-generated text increasingly difficult to distinguish from human-written text. This creates challenges in academic integrity, authorship verification, and the evaluation of student writing.

This project investigates methods for detecting AI-generated essays and identifying the linguistic characteristics that distinguish human-written from AI-generated text. Rather than stopping at a binary *Human / AI* decision, the project also evaluates how well detectors generalize to text generated by **LLMs that were never seen during training** — one of the weakest points of current AI-text detectors.

The project combines:
- **Linguistic / stylometric feature analysis** (RQ1)
- **Traditional machine learning** on TF-IDF + engineered features (RQ2)
- **Fine-tuned transformer models** (RQ2)
- **Cross-LLM external benchmarking** on essays generated by five modern LLMs (RQ3)

---

## 2. Research Questions

### RQ1 — Discriminative linguistic features
**Which linguistic features most clearly distinguish human-written essays from LLM-generated essays?**

### RQ2 — Model comparison
**Which model family achieves the highest detection accuracy — TF-IDF + gradient boosting (LightGBM/XGBoost) or fine-tuned transformers (DistilBERT/RoBERTa/modernBERT/DeBERTa)?**

### RQ3 — Cross-LLM generalization
**How much does detection performance drop when a model is evaluated on essays generated by LLMs and under prompting conditions not represented in its training data?**

## 3. Datasets

### 3.1 Development dataset — DAIGT V2
- **Source:** DAIGT V2 training set (`data/raw/raw_data.csv`)
- **Raw size:** 460,364 essays with fields `text, label, prompt_name, source, RDizzl3_seven`
- **After cleaning:** ~44,854 validated essays (missing/short/outlier/duplicate removed; see `notebooks/02_data_cleanning.ipynb`)
- **Label convention:** `0 = Human`, `1 = AI-generated`

### 3.2 RQ3 external benchmark (unseen-LLM test)
A held-out benchmark of **2,000 essays** built specifically to test generalization, stored under `data/rq3/`:

| Component | File | Size |
|---|---|---|
| Human holdout | `rq3_human_holdout_1000.csv` | 1,000 human essays |
| AI-generated | `rq3_ai_1000.csv` | 1,000 AI essays |
| Merged benchmark | `rq3_external_benchmark_2000.csv` | 2,000 essays |

**AI essays** were generated through OpenRouter from **five modern LLMs** (200 essays each):
- `openai/gpt-5.6-terra` (GPT family)
- `anthropic/claude-sonnet-5.5` (Claude family)
- `google/gemini-3.8-flash` (Gemini family)
- `meta-llama/llama-3.3-70b-instruct` (Llama family)
- `deepseek/deepseek-v4-pro-0813` (DeepSeek family)

across **10 essay prompts** and **4 generation conditions** (250 essays each):
- `standard` — default instruction-following generation
- `natural` — prompted to write more naturally
- `student_style` — prompted to mimic a student writing style
- `post_edited` — generated by one LLM and paraphrased/edited by a second LLM

Full audit trail (tokens, cost, serving provider, timestamps, quality status) is kept in `rq3_ai_1000.csv` and `rq3_generation_errors.jsonl`. Generation is driven by `generate_rq3_essays.py` + `rq3_generation_config.json`.

> **Leakage rule (RQ3):** Once AI generation begins, all detector checkpoints are frozen. No model is trained or threshold-tuned on the 2,000-row external benchmark.

## 5. Linguistic Features (RQ1)

Eight engineered features are extracted from each essay (see `src/pipelinebuilder.py → LinguisticFeatureExtractor` and `notebooks/04_important_feature.ipynb`):

| # | Feature | Interpretation |
|---|---|---|
| 1 | `avg_word_length` | Average characters per word |
| 2 | `punctuation_ratio` | Punctuation density relative to words |
| 3 | `burstiness` | Variation in sentence length (std of sentence lengths) |
| 4 | `word_count` | Essay length |
| 5 | `function_word_ratio` | Share of stop/function words |
| 6 | `avg_sentence_length` | Average words per sentence |
| 7 | `lexical_diversity` | Type-token ratio (unique / total words) |
| 8 | `sentence_count` | Number of sentences |

### RQ1 key findings
All eight features are statistically significant (p ≈ 0). Ranked by discriminative power:

| Rank | Feature | Corr. with label | Cohen's d | Univariate AUC | RF importance |
|---|---|---|---|---|---|
| 1 | **avg_word_length** | +0.576 | **1.45 (Large)** | 0.835 | 0.32 |
| 2 | punctuation_ratio | +0.328 | 0.71 | 0.689 | 0.18 |
| 3 | burstiness | −0.322 | −0.70 | 0.234* | 0.15 |
| 4 | word_count | −0.263 | −0.56 | 0.374* | 0.13 |
| 5 | function_word_ratio | −0.264 | −0.56 | 0.366* | 0.09 |
| 6 | avg_sentence_length | −0.151 | −0.31 | 0.441 | 0.08 |
| 7 | lexical_diversity | +0.182 | 0.38 | 0.593 | 0.07 |
| 8 | sentence_count | −0.169 | −0.35 | 0.418 | 0.07 |

\* AUC < 0.5 means the feature is inversely correlated with the AI label (humans score higher); direction is captured by the sign of correlation/Cohen's d.

- **Average word length is the single strongest signal** — AI essays consistently use longer words.
- Random Forest and LightGBM feature rankings agree strongly (Spearman ρ = 0.93).
- Permutation importance confirms the same top-4 ordering when measured by actual F1 drop.

## 6. Models & Results (RQ2 — in-distribution test)

Evaluation protocol: 80% train pool / 20% held-out test. Transformers use an inner 90/10 train/validation split with early stopping, then are retrained on the full train pool for the selected number of epochs. All results below are on the same 20% test set.

### 6.1 Traditional ML — TF-IDF (1–2 grams, sublinear TF, max 10k features) + linguistic features
Source: `notebooks/ml_results_summary.csv`, `notebooks/05_LG_RF_LGBM_XGB_SVM.ipynb`

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC | CV F1 (mean ± std) | Train time |
|---|---|---|---|---|---|---|---|
| **LightGBM** | **0.9945** | 0.9971 | 0.9889 | **0.9930** | 0.9995 | 0.9927 ± 0.0007 | 6m 51s |
| XGBoost | 0.9934 | 0.9945 | 0.9886 | 0.9915 | 0.9993 | 0.9918 ± 0.0002 | 9m 19s |
| SVM | 0.9929 | 0.9965 | 0.9851 | 0.9908 | 0.9993 | 0.9888 ± 0.0015 | 13m 07s |
| Logistic Regression | 0.9917 | 0.9920 | 0.9869 | 0.9894 | 0.9991 | 0.9881 ± 0.0008 | **11s** |
| Random Forest | 0.9891 | 0.9953 | 0.9766 | 0.9859 | 0.9986 | 0.9855 ± 0.0016 | 2m 54s |

**LightGBM** is the best traditional model; **Logistic Regression** is the best speed/accuracy trade-off.

### 6.2 Fine-tuned transformers
Source: `notebooks/transformer_comparison.csv`, `notebooks/06_modernBERT_deBERTa.ipynb`, `notebooks/07_DistilBERT_RoBERTa_synced.ipynb`

**RQ2 conclusion:** On in-distribution data, fine-tuned transformers (modernBERT, DeBERTa-v3) edge out gradient boosting, but the gap is small (~0.5 F1). Traditional models remain strong, fast, and fully interpretable baselines.

## 7. Cross-LLM Generalization (RQ3)

RQ3 tests whether detectors that score ~99% in-distribution keep their performance on essays from **unseen LLMs** and **unseen generation styles**.

### Workflow (final run order — `notebooks/RQ3_RUN_ORDER_FINAL.md`)
1. `08_RQ3_01_prepare_human_holdout.ipynb` — isolate 1,000 human essays never used in RQ2 training.
2. `09_RQ3_02_retrain_traditional_ML.ipynb` — retrain LightGBM/XGBoost/SVM/LR/RF with early stopping.
3. `10_RQ3_03_retrain_ModernBERT_DeBERTa.ipynb` — retrain modernBERT / DeBERTa-v3.
4. `11_RQ3_04_retrain_DistilBERT_RoBERTa.ipynb` — retrain DistilBERT / RoBERTa.
5. `12_RQ3_05_generate_1000AI_OpenRouter_VERIFIED.ipynb` (+ `generate_rq3_essays.py`) — generate 1,000 AI essays from 5 LLMs via OpenRouter (dry-run → smoke → production, with checkpointed resume).
6. `13_RQ3_06_merge_and_evaluate_external.ipynb` — merge into the 2,000-row benchmark and evaluate every retrained detector: accuracy, precision/recall/F1, AUROC, **human false-positive rate**, performance by generator family, by generation condition, and performance drop vs. internal evaluation.

## 8. Evaluation Metrics & False-Positive Analysis

Because an AI-text detector can have high accuracy yet still produce unacceptable false positives (human essays flagged as AI), the project reports:
- Accuracy, Precision, Recall, F1-score, ROC-AUC, Confusion Matrix
- **Human False Positive Rate** (explicitly tracked in RQ3)
- Performance breakdown by generator family and generation condition
- Performance drop between in-distribution and external evaluation

A detection result is interpreted as a **model-based estimate of AI-likeness**, never as definitive proof of authorship.

## 12. Limitations

- **In-distribution vs. external gap:** ~99% F1 on the DAIGT V2 test set does not guarantee equal performance on essays from newer LLMs; RQ3 quantifies this drop.
- **False positives:** Polished, formal, low-error human writing can resemble AI text. The project tracks human FPR explicitly.
- **LLM evolution:** As generators improve, discriminative features (e.g., word length) may weaken; the five-LLM RQ3 benchmark is a snapshot in time.
- **Human–AI co-authorship:** Binary classification is insufficient for mixed authorship; percentage-style AI-likeness estimation is a planned extension.
- **Detection ≠ proof:** No detector output should be treated as definitive evidence of authorship.
